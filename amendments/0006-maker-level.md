# Amendment 0006: the maker level

**Status:** applied to `SPEC.md` v0.3.6
**Target:** `SPEC.md` v0.3.5
**Date:** 2026-10-17
**Ruling:** R34 as corrected by Pablo the same day; he chose the name "maker".

Amendment 0005 redefined `practitioner` as the seasoned vibe-coder. Pablo corrected that. A practitioner is
someone acquainted with coding but not with software engineering: an engineer of another discipline, or a
self-taught coder. That leaves a gap between newcomer and practitioner, so there is now a fourth level:

- `newcomer`: a first product, or casual vibe-coding;
- **`maker`** (new): a seasoned vibe-coder who has built several products with AI, is learning the process,
  and isn't fluent in code;
- `practitioner`: acquainted with coding, not with software engineering;
- `professional`: a software engineer.

§3.3 and §5.3 gain a `maker` row. The guidance for a maker is ASM-59: the guided questions in fewer, larger
rounds with only new terms explained, or an AI-reprocessed prompt the maker confirms. This amendment supersedes
the definition in amendment 0005.
